# Contract: Authentication (ports and HTTP API)

Server use cases in `src/application/auth/`, driven by route handlers (driving adapters) and depending only on ports: `UserRepository`, `SessionRepository`, `MagicLinkTokenRepository`, `Mailer` (SMTP adapter), `OAuthProvider` (Google OIDC adapter, `openid-client`), `TokenGenerator`. The client sees only the `AuthGateway` port (HTTP adapter). No passwords.

`OAuthProvider` port: `begin() -> { redirectUrl, flowState }` and `complete(callbackParams, flowState) -> { authenticated, identity: { email, googleSub } } | { rejected, reason }`. The Google adapter (`src/adapters/google/`) implements it with `openid-client` (PKCE, state, nonce, id-token verification, verified email required); library types never leave the adapter. The magic link is in-house: `verifyMagicLink(token)` returns the identity `{ email }`. After an authenticated identity from either path, the `signInWithIdentity` use case finds or creates the user and creates the session (server-side, in PostgreSQL).

## Endpoints
| Method and path | Purpose |
|-----------------|---------|
| `POST /api/auth/magic-link` `{ email }` | Creates a single-use token (stored hashed, expires in about 15 minutes), emails the link `/auth/verify?token=...`. Always answers the same way, known email or not. |
| `GET /auth/verify?token=` | `verifyMagicLink` consumes the token atomically (valid, unexpired, unused); then creates the user if new, creates a session, sets the cookie and redirects to `/`. Expired or used tokens redirect to `/sign-in` with an error code. |
| `GET /api/auth/google` | Starts Google OAuth through `OAuthProvider.begin` (authorization code with PKCE, state and nonce; `flowState` kept in a short-lived HttpOnly cookie) and redirects to Google. |
| `GET /auth/callback` | `OAuthProvider.complete` verifies state and nonce, exchanges the code, verifies the id token and requires a verified email; then finds or creates the user by `google_sub` or verified email, creates a session and redirects to `/`. |
| `GET /api/auth/session` | `{ userId, email }` for a valid session, 401 otherwise. Extends the sliding expiry. |
| `POST /api/auth/sign-out` | Same-origin only. Deletes the session and clears the cookie. |

## Session and token rules
- Session cookie: opaque random value, HttpOnly, Secure (except local development), SameSite=Lax, path `/`; only its hash is stored, with `expires_at` (sliding).
- Tokens and sessions are generated by the `TokenGenerator` port (cryptographically secure randomness).
- An expired or invalid session yields 401; the client keeps local data usable and shows a non-blocking re-auth prompt.
- Configuration (environment, validated at startup): `DATABASE_URL`, `APP_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
