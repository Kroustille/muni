# Data Model: Muni v1

## Item (single `items` table locally and in PostgreSQL)

| Field | Type | Applies to | Rules |
|-------|------|-----------|-------|
| `id` | uuid (client-generated) | all | server primary key is `(user_id, id)`, so ids cannot collide or leak across users |
| `user_id` | uuid | all | server only, taken from the session, never accepted from the client; not part of `ItemWire` |
| `type` | enum `shopping\|book\|movie\|recipe` | all | immutable after creation |
| `title` | text | all (name for shopping) | required, trimmed, non-empty (edge case) ; duplicates allowed |
| `created_at` | timestamptz | all | set once (FR-008) |
| `author` | text null | book | |
| `status` | text null | book, movie | book: `to_read\|reading\|read`; movie: `to_watch\|watched`; default first value |
| `recommended_by` | text null | book, movie | free text (FR-009) |
| `rating` | smallint null | book, movie | 1..5; kept but hidden unless status is read/watched |
| `notes` | text null | book, movie, recipe | |
| `quantity` | text null | shopping | free text (e.g. "2", "500 g") |
| `checked` | boolean | shopping | default false |
| `ingredients` | jsonb null | recipe | ordered array of `{quantity, name}`; one LWW field |
| `steps` | jsonb null | recipe | ordered array of strings; one LWW field |
| `deleted_at` | timestamptz null | all | soft delete; LWW like any field |
| `fields_updated_at` | jsonb | all | map field name to HLC string `<wallMs>-<counter>-<deviceId>` |
| `server_updated_at` | timestamptz | all | set by server on every accepted write; pull cursor |

Validation (shared domain zod schema, applied by the sync service and mirrored by SQL CHECK constraints): type-specific fields must be null for other types; status values per type; rating between 1 and 5.

## Recipe sub-structures
- **Ingredient**: `{ quantity: string, name: string }`, order significant.
- **Step**: string, order significant.

## Derived (not stored)
- **Recommender name**: distinct non-empty `recommended_by` values from the user's non-deleted items.
- **List counts and recent items**: queries over `type` and `created_at` excluding deleted rows.

## Local-only stores (IndexedDB)
- `items`: mirror of the table above.
- `outbox`: set of item ids with pending changes.
- `meta`: `{ pullCursor, deviceId, hlcState, userId }`.

## Server-only tables (PostgreSQL, created by Kysely TypeScript migrations in `db/migrations/`, types generated by `kysely-codegen` into `src/adapters/postgres/db-types.ts`)
- `users`: `id` uuid, `email` unique (lowercased), `google_sub` unique null, `created_at`.
- `sessions`: `id`, `user_id`, `token_hash` unique, `created_at`, `expires_at`, `last_seen_at`.
- `magic_link_tokens`: `id`, `email`, `token_hash` unique, `expires_at`, `consumed_at` null (single use).
- `items`: as above with primary key `(user_id, id)` and an index on `(user_id, server_updated_at)`.

## State transitions
- Book: `to_read` → `reading` → `read`, any direction allowed; rating editable only when `read`.
- Movie: `to_watch` ↔ `watched`; rating editable only when `watched`.
- Shopping: `checked` toggles freely.
- Any item: active → deleted (`deleted_at` set) → restored via undo (`deleted_at` cleared with newer timestamp). Deleted rows are retained for sync; purge is out of scope in v1.

## Merge rule
For each field `f`, the value with the greater `fields_updated_at[f]` wins (ties broken by device id). Applied by the same domain `merge` in the server sync service (push) and in client pull handling.

## Isolation rule
Server-side authorization: the user id comes only from the session. Every server repository method takes `userId` and scopes by it; rows are never deleted (soft delete only). Verified by two-user isolation tests at use-case, PostgreSQL adapter and route handler level.
